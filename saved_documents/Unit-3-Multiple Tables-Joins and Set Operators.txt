SQL JOINS & SET OPERATORS  JOIN  •   A   JOIN   is used when required data is stored in more than one table.  •   Related tables are connected using a common column.  •   Usually, the common columns are:  •   Primary Key in one table  •   Foreign Key in another table  •   A join condition tells Oracle which rows should be matched.

Cartesian Product  •   Occurs when   two tables are queried without a join condition .  •   Every row in the first table is combined with   every row in the second table .  •   If one table has   m rows   and another has   n rows :  Total rows = m × n  Example:  SELECT s.Last, s.First, f.Name  FROM student s, faculty f;  If:  •   STUDENT = 6 rows  •   FACULTY = 8 rows  Then:  6 × 8 = 48 rows  Sample Output
Types of joins in Oracle:  1.   Equijoin.  2.   Nonequijoin.  3.   Outer join.  4.   Self-join.
Equijoin  •   The equijoin is a join with a join condition involving common columns from two tables.  •   Matches rows from two tables using the = operator.  •   Usually connects a Primary Key with a Foreign Key.  •   Only matching rows are returned.  The syntax is  SELECT   columnnames  FROM   tablenames  WHERE   join condition(s);
SELECT s.Last || ', ' || s.First AS STUDENT,  f.Name AS FACULTY  FROM student s, faculty f  WHERE s.FacultyId = f.FacultyId;  If a faculty member has   no matching student , that faculty member will   not appear   in an equijoin.
Joining Three Tables  •   When data is required from   three tables , more than one join condition is needed.  •   For   N tables , normally   N − 1 join conditions  are required.  SELECT e.Lname || ', ' || e.Fname AS EMPLOYEE,  d.DeptName AS DEPARTMENT,  p.PosDesc AS POSITION  FROM employee e, dept d, position p  WHERE e.DeptId = d.DeptId  AND e.PositionId = p.PositionId;

Table Aliases  •   A   table alias   is a short name given to a table.  •   It makes queries   shorter and easier to read .  •   Alias is specified in the FROM clause.  FROM employee e, dept d, qualification q  e.DeptId  d.DeptName  q.QualDesc  Instead of:  employee.DeptId  dept.DeptName  qualification.QualDesc  •   We can use   AND   along with join conditions.  •   This allows us to   filter the joined result  SELECT e.Lname, d.DeptName  FROM employee e, dept d  WHERE e.DeptId = d.DeptId  AND e.DeptId = 10;  •   Join the tables and display only employees belonging to Department 10.
Nonequijoin  •   The   join   condition   for   these   tables   can be written using any operator other than the = operator.   That   is   why   it   is   called   non- equijoin.  •   It can use operators such as: > , <, >= ,<=  BETWEEN
SELECT e.Lname, e.Salary, l.LevelNo  FROM employee e, emplevel l  WHERE e.Salary BETWEEN l.LowSalary AND l.HighSalary;  EMPLEVEL  LevelNo   LowSalary   HighSalary  1   20,000   29,999  2   30,000   59,999  3   60,000   99,999  Employee  Employee   Salary  Shaw   24,500  Garner   45,000  Chen   35,000  Roberts   75,000

Outer Join  Problem with Equijoin  •   An equijoin returns only matching rows.  •   If an employee has no qualification, that employee is excluded.  •   An   outer join   also displays the unmatched row.  •   The missing values are displayed as NULL.  •   Oracle's traditional syntax uses (+).
The general syntax is  SELECT   tablename1.columnname, tablename2.columnname  FROM   tablename1,   tablename2 WHERE  tablename1.columnname   (+) =  tablename2.columnname;  SELECT   e.Fname || ', ' || e.Lname AS EMPLOYEE,  q.QualDesc  FROM employee e, qualification q  WHERE   e.QualId   =   q.QualId (+);
Equijoin:   unmatched employee is removed.  Outer join:   unmatched employee is included with   NULL .
Self-Join  •   A self-join is joining a table to itself.  •   The same table is treated as two different copies using aliases.  •   Useful for finding employee–supervisor relationships. SET OPERATORS  SET OPERATORS  •   Set operators combine the results of two separate SELECT queries.  •   The   implementation   of   these   operations   is through the use of set operators.  •   The union compatibility is achieved or the set operations are performed on results from two independent queries.  •   The output from both queries must return the same   number   of   columns,   and   respective columns must have a similar domain.
Set Operator   Use  Union   It returns all rows from both queries, but  duplicate rows are not repeated  Union All   It returns all rows from both queries, and it displays all duplicate rows  Intersect   It returns all rows that appear in both queries’ results.  Minus   It returns rows that are returned by the first query minus rows that are returned by the second query.  Important Rule  Both queries should have:  •   Same   number of columns  •   Corresponding columns with   compatible data types
